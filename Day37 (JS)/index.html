strict vs non-strict mode

  • Earlier The philosophy was, "Don't stop the code from running, even if something looks wrong. Just make a guess and keep going." This is Non-Strict Mode, often called "sloppy mode."
  • This causes 'silent' errors because code might run, but it might be doing something completely different. The problem is that it hides potential bugs
  • The First Principle of Strict Mode: Its purpose is to change "sloppy" JavaScript that has silent errors or "bad syntax" into code that throws immediate, obvious errors. It helps you write better, safer code by forcing you to be more explicit.

Strict mode features

  • 1. Prevents Accidental Global Variables

    • In non-strict mode, if you assign a value to a variable that hasn't been declared, JavaScript "helpfully" creates that variable on the global object (window). This is a huge source of bugs.

  • 2. Changes the Behavior of this

    • In non-strict mode, this defaults to the global Object (window).
    • In strict mode, this is undefined. This prevents from accidentally modifying the global Object.

  • 3. Prohibits Duplicate Parameter Names

    Its a bad practice and strict mode prohibits it.

    • In Non-strict mode the last parameter wins and there is no error
    • In strict-mode, This is a syntax error and the code won't run

  • 4. Makes eval() Safer

    The eval() function is powerful and dangerous because it can execute arbitrary strings as code. Strict mode puts a cage around it.

    • In Non-strict mode eval() can create a new variable in its surrounding scope
    • In strict mode, variables created in the eval() call stays inside the eval()s scope

  • 5. delete myVar

    'delete' cannot be called on an identifier in strict mode.

    • In Non-strict mode, no errors
    • In strict mode, 'SyntaxError: Delete of an unqualified identifier in strict mode.'

  • 6. Octal numbers

    Octal number are those of binary octal numbers

    • In Non-strict mode, no errors and prints the number representing it
    • In strict mode, 'SyntaxError: Octal literals are not allowed in strict mode'

Still 'use strict' is being used

  1. JavaScript Modules (import/export) are always in strict mode.
  2. Code inside a `class` body is always in strict mode.

This Keyword

  • In Non-Strict mode
    • In node.js environment this points to the {} empty object
    • In browser environment this points to the window object
  • In Strict mode
    • In node.js environment this points to the {} empty object
    • In browser environment this points to the window object

Call, Apply, Bind Method

These methods are used to when working with functions, they ley u control the value of this inside a function

  • Call Invokes the function immediately, passing arguments one by one
  • func.call(thisArg, arg1, arg2)
  • Apply Invokes the function immediately, but arguments are passed as an array
  • func.apply(thisArg, [arg1, arg2])
  • Bind Returns a new function with this permanently set, without invoking it right away
  • const newFunc = func.bind(thisArg, arg1, arg2, ...)
  • Note: here the "this" points to the invoking object

Arrow Functions

Arrow functions do not have their own this. They inherit this from their parent scope, just like any other variable.
